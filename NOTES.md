# Notes from the golfing sessions

Work by Albert with Claude. Every C version in `c/history/` passed the checks in `test/`
(ASan/UBSan, TREE(1)=1, TREE(2)=3, 3,000 embedding pairs, 286 generated trees).

## Ground rules
- No fixed limits ("it has to work"): the 829-char capped version was rejected.
- gcc on x86-64 only (implicit int, K&R parameters, GNU `?:`, built-in `realloc`).
- From 816 chars on, the colour count is fixed at 3 (TREE(3) only).

## Ideas that were tested and rejected
- `P[p][1]=p++`: unsequenced, segfault.
- `return!i<I` (four times): parses as `(!i)<I`; 1,496 mismatches, TREE(2)=2.
- Globalising `c`, `k`, `b` in recursive functions: TREE(2)=2.
- Unparenthesised `#define A(n)n<0?-n:n`: misparses inside `i+A(x[i])`, runs out of memory.
- Removing `abs` from the sibling step: marked children step backwards, infinite loop.
- Removing the self-comparison check: x and y alias, marking corrupts both, out of memory.
- `int*S` holding pointers: truncation, segfault.
- Argument-pointer access (`(&x)[1]`): undefined on x86-64 (arguments in registers).

## Pasted analyses that were checked
- "Global k/c and bzero are bugs; corrected version is 598 chars": the code was 795 chars and the bugs did not exist.
- "Unsequenced side effect in `*P[p++]=1`": incorrect; `p` is read once, so it is well-defined.
- "Falling off the end of `f` is UB when its value is used": correct; fixed with `? :` in the 761 version.
- "P(reaching 561 from 595) is about 0.25%": 561 was reached about 20 minutes later.
